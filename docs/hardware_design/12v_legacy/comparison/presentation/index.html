What We're Deciding

The question

Which hardware design should an engineer build now?

The answer must consider power safety, LiPo charging policy, hand assembly, and whether the active firmware can run today.

The 9 designs

  1. 5V Legacy
  2. Original 12V
  3. 12V All-THT
  4. V2 Industrial
  5. V3-A Simple
  6. V3-B + CN3722
  7. V3-C + XL4016
  8. V3-D Onboard 3S Module
  9. Final Design
Three key shifts: 5V to 12V, Schottky OR to active Q_BATT, and Wemos D1 R32 to ESP32-S3.

Why it wins
  • Single 12V-only configuration
  • Active adapter priority with Q_BATT
  • D_ADAPT prevents adapter-sense backfeed
  • External balance charging handles termination and balancing
  • ESP32-S3 long-term platform
If onboard charging is mandatory, develop V3-D separately: Option A is 12.6V/2A + 25/40A BMS + 15V/3A. Use USB-C only after exact-module 3S validation; avoid parallel load charging.

Remaining tasks

  1. Add an ESP32-S3 PlatformIO environment.
  2. Move GPIO definitions to the final pin map.
  3. Prefer PCNT-based quadrature counting such as ESP32Encoder.
  4. Retest WiFi, TCP, dashboard, calibration, ADC, and all encoders on hardware.

Bottom line

Build Final Design for the next core sensor board.

If onboard charging becomes mandatory, prototype V3-D with charge-only mode before moving to power-path/load-sharing.

Use Wemos-era boards only when immediate current-firmware compatibility matters more than the ESP32-S3 hardware direction.
