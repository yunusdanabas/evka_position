Hardware Comparison

Choosing the right board for new builds

April 2026

What We're Deciding

Question: Which hardware version should we build for a new EVKA core sensor?

Options:

  • 5V Legacy — Wemos, 1S LiPo, bench reference
  • Original 12V & 12V All-THT — Wemos, 3S with unsafe TP5100 charging
  • V2 Industrial — ESP32-S3, RS-485, hardware watchdog
  • V3-A Simple — ESP32-S3, clean 12V core
  • V3-B / V3-C — Onboard charging branches (15V)
  • Final Design — ESP32-S3, 12V, external charging, documented Q_BATT

Original 12V

%%{init: {'theme': 'dark'}}%% graph TD EXT["12V adapter"] --> RPP["AO4407A SOIC-8\nreverse polarity P-FET"] RPP --> V12["V12_PROT"] V12 --> DE["D_EXT SS34"] DE --> BIN["BUCK_VIN\nSchottky OR"] V12 --> MT["MT3608 boost\n12V to 15V"] MT --> TP5["TP5100\n2S MAX - 8.4V limit\nCannot charge 3S"] TP5 --> BMS["HX-3S-01 BMS"] BMS --> DB["D_BAT SS34"] DB --> BIN BIN --> BUCK["MP1584EN\n12V to 5V"] BUCK --> R["5V_RAIL"]
CRITICAL: TP5100 is a 1S/2S charger only. Max output 8.4V. Cannot charge 3S to 12.6V.
Best part: First useful 12V conversion. MP1584EN + LC filter establishes 3S/12V architecture.

Best for: Historical reference only. Do not use for new builds.

12V All-THT + 2S LiPo Option

2S LiPo Alternative Advantage Trade-off
2S × 3.7V = 7.4V nominal TP5100 works correctly at 8.4V max Energy 16.3 Wh vs 3S 24.4 Wh (same Ah)
Schottky OR priority 12V adapter (11.6V) always wins vs 2S full (8.0V) Lower backup runtime
Verdict: 2S is viable IF the architecture is changed to 2S. But Final Design is 3S + external charging, so this is a historical option.
12V All-THT weaknesses: Does not fix TP5100 3S error or Schottky OR ambiguity. Through-hole makes it easier to hand-solder, but electrical problems remain.

V3-A Simple

%%{init: {'theme': 'dark'}}%% graph TD EXT["12V adapter"] --> RPP["IRF4905\nreverse polarity"] RPP --> V12["V_PROT"] V12 --> BIN["BUCK_VIN"] V12 --> DG["D_GATE"] DG --> G["Q_BATT gate"] RG["100k pull-down"] --> G BAT["3S LiPo"] --> FB["5A fuse"] FB --> BMS["BMS_3S"] BMS --> QB["Q_BATT IRF4905"] G --> QB QB --> BIN BIN --> BUCK["MP1584EN"] BUCK --> R["5V_RAIL"]
Best part: Cleanest safe 12V core before Final Design. Q_BATT without industrial bloat.
Weaknesses: Lacks D_ADAPT isolation diode. Optional charging/zener variants increase decision ambiguity.

Best for: reference. Use Final Design instead for new boards.

V3-B + CN3722 / V3-C + XL4016

V3-B: CN3722 Solar MPPT Charger

15V adapter required. CN3722 is a real 3S CC/CV charger controller (not TP5100). CHRG status pin (active low during charge).

Real 3S charging No onboard balancing Needs 15V

V3-C: XL4016 CC/CV Buck Module

Generic adjustable buck preset to 12.60V. Useful for bench, not unattended charging. No automatic LiPo termination.

Float-charge risk Trimpot drift Lab only

Best for: V3-B when onboard charging is mandatory and 15V is acceptable. V3-C for supervised lab fallback only.

Final Design

%%{init: {'theme': 'dark'}}%% graph TD EXT["12V adapter"] --> F1["Fuse/PTC"] F1 --> TVS["P6KE18A TVS"] TVS --> RPP["Q_RPP IRF4905\nreverse polarity P-FET"] RPP --> V["V_PROT"] V --> DA["D_ADAPT SS36\nadapter isolation"] DA --> BIN["BUCK_VIN"] V --> DG["D_GATE 1N5819"] DG --> G["Q_BATT gate\n~11.7V with adapter"] RG["100k pull-down"] --> G BAT["3S LiPo XT60"] --> FB["5A blade fuse"] FB --> BMS["BMS_3S\nprotection only"] BMS --> QB["Q_BATT IRF4905\noff with adapter on without"] G --> QB QB --> BIN BIN --> CB["470uF hold-up"] CB --> BUCK["MP1584EN\n5.05V"] BUCK --> R["5V_RAIL"]
Best part: One unambiguous build baseline.
D_ADAPT: Prevents battery backfeed into adapter-sense rail when unplugged.
Q_BATT margin: Vgs = -0.9V (worst case), 1.1V margin to Vgs(th) = -2V. Safe.
12V only: No 15V variants, no charger ambiguity.

Source Selection: Schottky OR vs Q_BATT

Schottky OR (5V, 12V, 12V-THT)

%%{init: {'theme': 'dark'}}%% graph LR A["12V adapter\n~11.6V"] -->|"D_EXT"| OR["BUCK_VIN\nhigher wins"] B["3S LiPo full\n~12.2V"] -->|"D_BAT"| OR OR --> L["Load"]

Problem: Full 3S pack (12.2V) exceeds 12V adapter (11.6V) after diode drops. Adapter priority is ambiguous.

Active Q_BATT (V2, V3, Final)

%%{init: {'theme': 'dark'}}%% graph LR A["Adapter present"] -->|"V_PROT high"| G["Q_BATT gate"] G -->|"Vgs ~0V"| Q["FET off"] B["3S LiPo"] --> Q Q -.-> L["Load blocked"] C["Adapter path"] --> L2["Load enabled"]

Solution: Adapter present = gate high = battery FET off = adapter always powers load. Final Design adds D_ADAPT to prevent backfeed.

Summary

5V Legacy Bench reference. Proven encoder conditioning baseline.
Original 12V / 12V All-THT TP5100 3S charging is unsafe/unverified. Do not use for new builds.
V2 Industrial RS-485/Modbus + hardware watchdog. Use only if expansion is real.
V3-A Simple Reference. Move to Final Design for new core boards.
V3-B / V3-C Onboard charging branches. V3-B (CN3722) if 15V acceptable. V3-C (XL4016) lab fallback only.
Final Design Recommended for new EVKA core sensor. 12V, ESP32-S3, Q_BATT + D_ADAPT, external balance charging, zero charger ambiguity.

Next steps: Build first board. Validate power rails, switchover, thermal behavior. Port firmware to ESP32-S3.
