# evka_gui — EVKA Unified Control GUI (canonical)

Single-window control panel + 3D view for v4 board bring-up and daily operation.
Opens maximized with a 50/50 control/plot splitter by default.

This is the canonical operator GUI for the current prototype. It is **sensor-frame-only**: live XYZ,
recordings, snapshots, saved points, and Quick IPT results do not receive an endpoint/world
transform. Software zero is a display/session offset.

**Transports:** Serial, WiFi/TCP (port 8080), WebSocket (port 80 `/ws`), CSV replay.
A dropped link **reconnects on its own** (exponential backoff, 1 s → 30 s); the
Disconnect button becomes **Cancel** while a retry is pending.

**Main panel:** live position and connection controls stay visible; IPT, Points,
Diagnostics, and Commands live in tabs. The compact protocol log is in the left
column, not a bottom dock.

**Toolbar:** Record, Freeze, Calibration…, WiFi Settings…, IPT plots…, Remote Tester…
(ButtonRemoteTest dev firmware), Capture/Clear/Export Snapshots, Export Saved Points CSV,
Open Dashboard, Export Session CSV.

**Record** writes the live stream as raw firmware `DATA,` lines — the format
`--replay` already reads, so a recording plays straight back. It works on every
transport (TCP sends `X,Y,Z` + `SENSOR,` instead of `DATA,`, and is re-serialised), and
it always stores **raw sensor-frame** values, never software-zeroed ones. The firmware
web dashboard records the same format, so you can record on a phone in the field and
replay it here.

**Freeze** pauses the *view* — the link stays up, command replies still land, and a
recording in progress keeps writing. Arming IPT clears it automatically, since capture
would otherwise collect nothing.

**Views:** software 3D trail + XY/XZ/YZ plots with layer toggles (trail / IPT / origin /
saved points), adjustable trail length, IPT overlays on 2D and 3D views. The 3D view
rotates on left-drag and zooms on the mouse wheel.

**Look and feel:** colours and button names come from
`docs/gui_unification/DESIGN_TOKENS.md` (mirrored in `tokens.py`), shared with the
firmware web dashboard so the two read as one product.

**Replay:** pause, speed, step, slider seek (rebuilds session state from frame 0).

**Profiles:** save/load/delete named connection presets (mode, host, port, replay path).

```bash
python -m tools.evka_gui                              # open disconnected
python -m tools.evka_gui --serial /dev/ttyUSB0 --baud 115200
python -m tools.evka_gui --tcp 192.168.1.50:8080      # AP direct
python -m tools.evka_gui --tcp 192.168.1.84:8080      # STA
python -m tools.evka_gui --ws 192.168.1.50            # WebSocket dashboard stream
python -m tools.evka_gui --replay frames.csv
```

**Quick IPT:** inline **Quick IPT** group — ARM, sweep, STOP, SOLVE, Copy P, export capture
CSV, add P to snapshots. Optional **IPT plots…** pop-out. Standalone: `python -m tools.ipt`.

**Calibration window:** wire/theta/phi PPR trials, plus an **Endpoint** tab that runs the
whole endpoint session — collect world/sensor pairs, assign each to the calibration or
validation set, **Generate report**, and read PASS/FAIL and per-point residuals.

The currently named **Deploy calibration.json** button is historical legacy behavior, not canonical
GUI deployment. No shared/default calibration JSON is checked in or auto-loaded. A passing session
JSON may be supplied explicitly only to the legacy visualizer; this GUI remains sensor-frame-only.
Resolve theta count loss before endpoint capture.

Points are read from and written to `docs/calibration/sessions/current/`
(`calibration_points.csv` / `validation_points.csv`) directly — those files are the session
state, so the tab and `python -m tools.calibration.report` always agree. **Import CSV** pulls
in an export from the web dashboard **CALIBRATE → ENDPOINT** tab. The report itself is
generated by `tools/calibration/report.py`; the GUI never fits the transform itself. See
[`docs/calibration/report_workflow.md`](../../docs/calibration/report_workflow.md).

Captured sensor XYZ is always **raw sensor-frame**, never software-zeroed — same rule as
Record, and required for a valid fit.

**Protocol log:** compact left-column panel — filter DATA / ACK / ERR / Other.

Modules: `gui.py`, `model.py`, `transport.py`, `ws_client.py`, `protocol_log.py`,
`session_utils.py`, `replay_utils.py`, `calibration.py`, `ipt_panel.py`, `ipt_window.py`,
`wifi_window.py`, `remote_window.py`. Tests: `tests/`.

Feature matrix and design history: [`tools/README.md`](../README.md) and
